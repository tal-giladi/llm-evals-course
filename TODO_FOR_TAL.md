## The most important thing to know

**The judge runs in every lab are generated by a seeded model of judge behaviour, not recorded from a
real model.** Each simulation says so in a visible banner, and the lessons say so in prose. Every
statistic — kappa, TPR, TNR, intervals, paired tests, gate simulations — is genuinely computed in the
learner's browser from those recorded verdicts, so the arithmetic and the workflow are real; only the
judge's behaviour is modelled.

The reason is practical: recording real judge runs means running judge models over ~6,000 item/config
pairs, which needs a GPU or a paid API, and none was available at build time.

**What this means for you:**

- The course teaches its method correctly and every number in it is reproducible. Nothing is fake.
- **Do not present any lab number as a published measurement of a named real model.** The lessons are
  written to avoid this, but it is worth a read-through of modules 5–7 specifically.
- Replacing the data with real recordings is a data-file swap, not a rewrite: `build/generate.mjs`
  emits `simulations/*/data.js`, and the browser code never imports the generator. A new
  `build/record-real.mjs` that produces the same shapes would drop straight in.

## If you want to swap in real judge runs

1. Keep every field shape identical: `items[]` with `human[variant].label` and `.category`,
   `judge_menu[]`, `runs[configId]["itemId|variant"] = [5 repeat verdicts]`, `cost[configId]`.
2. Replace the emission step in `build/generate.mjs` with real model calls, keeping the seeded
   per-`(config, item, variant)` keying so runs stay resumable.
3. Re-run `node build/verify.mjs`. It asserts the properties the lessons claim. Some checks will
   legitimately fail — that is the signal that **the lesson text needs updating to match reality**,
   which is exactly what it is for.
4. Re-run `node build/smoke.mjs`.

## Known simplifications, stated rather than hidden

- **`doubled` is a dead field in the recipe lab.** `simulations/code-checks/app.js` computes a
  doubled ingredient quantity that no metric reads, so the "Break the metric" button only changes
  length, not correctness. Lesson 03.3 is written around what actually happens (ROUGE-L's recall
  half is already saturated, so padding moves only the precision half) and does not claim
  otherwise, but the doubling is inert and a future revision should either surface it in a
  field-accuracy check or drop it.
- **There is no judge picker in the release-gate lab.** `ab-gates` hardcodes one judge, and
  lessons 10.1–10.3 say so. Adding a picker means re-measuring those lessons.
- **The gate grid and the Items knob sample differently** — the grid takes a prefix of the item
  order, the knob draws. Lesson 10.3 flags this for the learner; it is worth making consistent
  if that lab is revisited.
- **`ab-gates` flip-list naming is asymmetric** — `paired.fixed`/`broke` are named from A's side
  while the panel's list is named from B's. Left in place deliberately: lesson 10.1 teaches it as
  a real trap in reporting.
